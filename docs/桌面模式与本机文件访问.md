# 桌面模式与本机文件访问

日期：2026-11-11。现已提供 Windows x64 便携 EXE 包，使用 PyWebView + WebView2 原生窗口和内置本机服务；未来可继续替换为 Tauri／Electron。

## 1. 统一文件接口

前端通过 `src/lib/localFiles.ts` 访问能力，不直接依赖桌面框架。服务端 `/api/v1/local/files` 接收授权 ID `grant`、相对 `path` 和 `operation`。

| 操作 | 行为 |
| --- | --- |
| list | 列出目录，最多 500 个条目 |
| read | UTF-8 文本读取，上限 1 MB |
| write | 创建新 UTF-8 文件，上限 1 MB；目标存在则失败 |
| mkdir | 新建目录，父目录需存在 |
| copy | 复制单文件到同一授权目录内的新目标，不覆盖 |
| move | 单文件复制成功后移除源，可用于重命名；不支持递归目录移动 |
| import | 将允许类型的图片／字体导入当前项目素材库，上限 32 MB；先同步项目 |

不提供删除、覆盖、运行程序和任意绝对路径读取。复制和移动不是事务操作，异常中断可能留下目标文件，需核对后再继续。

Agent 工具：`files.roots {}` 列出授权；`files.execute {grant,path,operation,target?,text?}` 操作文件。通过 `tools.discover` 检索 `files` 加载参数。模型没有目录授权工具。

## 2. 目录授权

项目“设置 → 本机文件访问 → 选择并授权文件夹”打开原生目录选择器。选择后确认是否允许写入；选择否则只读。可刷新授权列表及撤销。

授权只在当前后端进程存活，重启需重新授权。Agent 只收到目录 ID 和名称，不能自行授权本机路径。相对路径使用 `/`，拒绝磁盘绝对路径、`..` 越界、反斜杠和 NTFS 流路径。路径解析会检查符号链接解析后的边界；不将此实现视为可抵御恶意本机进程并发替换目录的操作系统沙箱。

文件选择器依赖 Python tkinter；之后封装桌面壳时可替换为原生 IPC，保持文件接口一致。目录授权／撤销只对当前进程有效，不与远程部署共享。

## 3. 用户数据与兼容

桌面启动模式默认 Windows 数据位置为 `%LOCALAPPDATA%/CardArts/data`，包括 SQLite、对象素材、上传临时文件、启动配置 `desktop.json` 和滚动日志 `logs/desktop.log`。其他系统使用 XDG 用户数据目录。

可用 `CARDARTS_DATA_DIR` 指定位置。内置图标作为程序资源读取，不复制到用户目录。显式数据库／存储环境配置仍优先，请检查已有 `.env`。

原开发模式默认路径保持兼容，不直接迁移或删除原 `data/`。浏览器 IndexedDB 也不会自动迁移到新的来源端口。切换桌面模式前请导出备份，并核对项目和素材的恢复；不要因为新界面为空就删除旧数据。

## 4. 本机服务认证

使用桌面启动器时只绑定 `127.0.0.1`，每次启动生成随机会话密钥。启动链接通过 URL fragment 临时传递密钥；前端立即清除 fragment，交换为 HttpOnly、SameSite=Strict 会话 cookie。

API 校验会话 cookie，拒绝不匹配的 Host 和跨来源 Origin。会话密钥不输出到日志。不同端口使用不同 cookie 名称。API、素材读取和本机文件操作共用该认证；静态前端页面无需认证。

此认证由 `CARDARTS_DESKTOP=1` 模式启用。原网页／云端部署没有因此自动获得用户账户系统，不要把开发模式暴露到公网。若直接设置桌面环境变量手工启动，还需要正确配置会话密钥；推荐使用启动器。

## 5. 启动与停止

先安装现有前后端依赖，再构建前端：

```powershell
npm --prefix frontend run build
```

之后双击项目根目录 `start-desktop.bat`，或执行：

```powershell
python backend/desktop.py
```

启动器在同一进程启动服务并托管已构建前端，无需另开 Vite。首次自动分配空闲端口，保存到用户目录；后续复用端口，保持浏览器本地数据来源稳定。已有端口被占用时会停止并提示，不杀占用进程、不静默换端口。

等待服务就绪后自动打开浏览器；30 秒未就绪会请求停止。设置 `CARDARTS_NO_BROWSER=1` 可禁用自动打开。

在启动终端按 Ctrl+C 关闭，或关闭该终端进程。关闭网页标签本身不会停止服务。本阶段没有引入独立辅助子进程，因此不存在按端口批量杀进程的清理逻辑；将来接入真正桌面外壳时仍需增加“窗口关闭 → 停止本机服务”的生命周期连接。

旧 `start.bat`／`stop.bat` 保持原开发流程，不能用旧 stop 脚本控制新桌面动态端口。不要删除 `desktop.json` 后期待浏览器原来源数据自动出现在新端口。

## 验证范围

- 前端构建、Agent 与设计回归通过。
- 后端本机文件测试：授权边界、撤销、只读、文本新建／读取、复制／移动、不覆盖、认证／Origin／Host 拦截通过。
- Windows 符号链接创建权限不足，对应测试跳过。
- 启动冒烟：独立测试数据目录、前端 HTTP 200、未认证 API 401、数据库生成通过；测试服务已关闭。
- 尚需人工验收：原生授权选择器、完整桌面浏览器认证交互、字体和图片导入、异常断电恢复、最终 EXE 打包与桌面窗口关闭联动。

## 连接已有文件夹的恢复修复

连接工作区现在先恢复再写回，支持按相对路径逐级读取项目文件；索引为空或缺失时扫描 projects/ 下的项目 JSON，并尝试恢复 assets/.assets.json 素材索引。首次连接后暂停自动写回，请核对项目列表后点击“立即落盘”开启。不能把服务端 data/ 目录当作浏览器文件夹工作区；应选择包含 cardarts.json 和 projects/ 的目录。此修复不会自动在你的真实目录执行恢复，也不会保证找回已被覆盖的项目正文；请先备份目录。

## 便携 EXE 包

release/CardArts-Windows-x64.zip 完整解压后运行 CardArts.exe，保留 _internal 目录。无需另装 Python/Node，需 Windows WebView2 Runtime。原生 EXE 关闭窗口会停止内置服务，已在隔离目录验收；前文关于终端关闭的说明仅适用于 python desktop.py 的浏览器开发入口。未逐项验收全部字体、打印与模型提供商。
